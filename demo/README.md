# InspectFlow 示範環境

本目錄提供可重建的示範資料、啟停腳本與人工點擊走查。所有公司、工程、
單位與人名都是虛構內容。示範資料一律經由正式後端 API 建立；前端和
示範使用者不會直接讀寫資料庫。

## 啟動與重建

先在目前 worktree 安裝依賴：

```bash
make setup
```

從 repo 根目錄啟動：

```bash
demo/scripts/start.sh
```

啟動腳本會在臨時工作目錄建立新的 SQLite 資料庫、執行 migration 與
初始化、啟動後端和 Vite，再載入 `demo/data/seed.json`。每次重新啟動都會
重建這個示範資料庫，確保帳號、任務與「總覽」數字一致。預設資料目錄是
`/private/tmp/inspectflow-demo`，不會使用 `backend/data/inspectflow.db`。

後端與前端預設都只綁定 `127.0.0.1`，同網段的其他裝置連不到；只有下方
HTTPS 手機走查模式會讓前端綁定區網 IP。`seed.py` 的 `--base` 與 e2e 的
`DEMO_BASE_URL` 只接受 `127.0.0.1`、`localhost`、`::1`，指到其他位址會
直接拒絕，避免把示範帳號寫進別人的環境。

工作目錄和連接埠可以分別設定；埠被其他程序使用時，腳本會停止並保留該
程序：

```bash
DEMO_WORK_DIR=/private/tmp/inspectflow-demo-2 \
BACKEND_PORT=8301 FRONTEND_PORT=5301 demo/scripts/start.sh
```

`DEMO_WORK_DIR` 同時決定 `demo.db`、log、結果檔與 PID 檔的位置。腳本先
確認 PID 的命令列符合預期才停止程序。停止服務時，使用啟動時相同的設定：

```bash
DEMO_WORK_DIR=/private/tmp/inspectflow-demo-2 \
BACKEND_PORT=8301 FRONTEND_PORT=5301 demo/scripts/stop.sh
```

## HTTPS 手機走查

需安裝 `mkcert` 並在這台電腦信任它的本機根憑證：

```bash
brew install mkcert
mkcert -install
demo/scripts/start.sh --https
```

命令會在示範工作目錄建立只含本機／區網 IP 的憑證，前端只綁定區網 IP，
並只接受同一個 `/24` 網段。手機與電腦需連到同一個 Wi-Fi，使用啟動輸出的
HTTPS 網址。iPhone 首次使用時，依 iOS「設定 → 一般 → 關於本機 → 憑證信任
設定」信任 mkcert 根憑證；根憑證路徑可用 `mkcert -CAROOT` 查詢。請勿將
私鑰或根憑證複製到 repo。

不用手機時，以 `http://localhost:5300/tasks` 開啟後切換瀏覽器為 360px 寬。

## 示範帳號

所有帳號的密碼只用於本機示範環境。請勿拿來連正式服務。

| 帳號 | 密碼 | 身分、登入後可見內容與兩層權限 |
|---|---|---|
| `admin` | `DemoAdmin2026` | 系統管理者；登入落在「總覽」；導覽有總覽、任務、專案、範本，另有「管理 ▾」（帳號、公司、角色、紀錄）；可新增帳號、查看一次性臨時密碼，並診斷及補上專案角色 |
| `demo-manager` | `DemoManager2026` | 主管；登入落在「總覽」，導覽只有「總覽」；可查看全公司專案進度與任務明細；不是任何專案的成員，沒有管理項目，也沒有帳號或專案寫入權限 |
| `demo-office` | `DemoOffice2026` | 內業工程師；登入落在「專案」，導覽只有「專案」；可開設專案、派出任務，並在專案查核項目頁套用範本；專案角色為「專案工程師」 |
| `demo-field-a` | `DemoFieldA2026` | 現場工程師；登入落在「任務」，導覽有「任務」與「專案」（唯讀已加入的專案）；可查看指派任務並開始查核；專案角色為「現場工程師」 |
| `demo-field-b` | `DemoFieldB2026` | 現場工程師；登入落在「任務」，導覽有「任務」與「專案」；可查看指派任務並開始查核；專案角色為「現場工程師」 |
| `demo-template-manager` | `DemoTemplate2026` | 範本管理者；登入落在「範本」，導覽只有「範本」；可管理範本庫；無專案存取權 |
| `demo-template-delegate` | `DemoDelegate2026` | 範本功能委派者；登入落在「帳號」，導覽只有「帳號」連結（沒有下拉）；只能為他人開通範本功能，不能新增帳號、改基本資料，也不能進公司、角色、紀錄；沒有範本管理權，看不到「範本」導覽 |
| `demo-consultant` | `DemoConsultant2026` | 外部協作；登入落在「專案」，導覽只有「專案」；只看得到被加入的專案（`DEMO-B`），唯讀；不能進入「範本」頁，在專案內只能唯讀瀏覽範本、不能套用 |
| `demo-no-access` | `DemoNoAccess2026` | 尚未開通任何功能；登入落在「設定」，沒有主導覽，畫面顯示「尚未開通任何功能，請洽系統管理者」 |

導覽只列帳號真的用得到的項目，不會出現點了才被擋的入口；直接輸入網址
進入沒有權限的頁面時，畫面顯示「無權限」，後端 API 同樣回 403。

專案角色與全公司的功能權限分屬兩層：單有功能權限不會自動取得專案內
的動作，專案內的動作要再有專案角色。內業工程師有「使用範本」功能，且
「專案工程師」角色可編輯查核項目，因此能在專案查核項目頁套用範本。外部協作
雖有「使用範本」功能，但「專案查閱人員」只有唯讀權限：不能進入「範本」頁，
在專案內只能唯讀瀏覽範本，看不到「套用至專案」，並提示「你沒有修改此專案查核項目的權限。」
獨立的「範本」導覽只提供給範本管理者與系統管理者。

委派者的畫面只列受委派範圍內的功能：為內部帳號開通時可以選「使用範本功能」
與「管理範本庫」；選外部帳號時不會出現「管理範本庫」。系統管理者新增帳號時
選職務（例如「現場查核」）並加入專案，建立完成畫面會顯示一次臨時密碼，離開後
就不再顯示；之後在該帳號的「為什麼他不能做這件事？」檢查任務清單時，可確認
「現場工程師」角色能讀取任務。「專案查閱人員」也能讀取查核任務；若要診斷
「管理專案成員」，選該操作與專案，缺少角色時畫面會列出可補上的角色，
「參與專案與角色」清單會同步更新。

## 預建資料

公司為「示範公司」，範本庫含「建築工程／給排水」下的排水坡度、
給水試壓與止水閥標示範本，以及「建築工程／電氣設備」的配電盤與接地
電阻範本。兩個專案皆由內業帳號開設，因此建立者自動成為
「專案工程師」成員。

| 專案 | 成員 | 任務資料 |
|---|---|---|
| `DEMO-A` 示範大樓機電工程 | 內業、兩位現場工程師 | 一筆待開始任務 |
| `DEMO-B` 示範廠擴建機電工程 | 內業、兩位現場工程師、外部協作 | 草稿、待開始、進行中、已完成、已取消任務各至少一筆 |

`COMPLETED` 任務是由 seed 以現場帳號呼叫既有 API 建立的教學紀錄；0.5.x
現場頁目前只支援開始任務。「總覽」因此同時有進行中、完成、待開始與取消
資料，方便示範計數與工作量的差異。`walkthrough` 草稿保留給下方真實點擊
流程。

## 真實點擊走查

安裝 Google Chrome 後，可用 Playwright 自動執行真實瀏覽器流程並保存截圖：

```bash
DEMO_WORK_DIR=/private/tmp/inspectflow-demo-e2e \
BACKEND_PORT=18310 FRONTEND_PORT=18311 demo/scripts/run-e2e.sh
```

腳本會重建隔離資料庫、使用 Chrome 點擊登入、派出任務、開始查核、套用範本、
逐帳號核對導覽與權限限制，以及新增帳號與角色診斷流程，並在
`demo/screenshots/` 寫入九張畫面；結束時只停止自己啟動的服務。也可依下方
步驟人工操作。自動化或人工流程的成功結果都應與截圖一併保存。

1. 以 `demo-office` 登入，開啟 `DEMO-B` 的「計畫與任務」，展開「示範廠擴建機電工程
   查核計畫」。確認「擴建廠機房派工示範」（地點「示範廠 A 棟機房」）
   是草稿，按該任務的「派出任務」，再按「確認」。畫面顯示「已派出任務，現場可以
   查看了。」，任務狀態變成待開始。
2. 以 `demo-field-a` 登入 `/tasks`，在「我的任務」找到同一個任務，開啟詳情並
   查看查核需求快照，按「開始查核」再按「確認」。畫面應顯示進行中。
3. 以 `admin` 或 `demo-manager` 重新登入，開啟「總覽」。在「專案進度」分頁確認
   任務數字與狀態已更新；切到「工程師工作量」分頁，確認可分別看到建議指派者
   與開始者。seed 的完成紀錄另提供已完成數字供比較。內業可到專案的「進度」
   看同一個專案的任務數字。
4. 以主管登入「總覽」，開啟專案進度與任務明細；依序登入範本管理者、委派者、
   外部協作及無權限帳號，確認導覽只有上表列的項目，直接輸入網址會看到
   「無權限」。
5. 以系統管理者開啟「管理 ▾」→「帳號」→「新增帳號」，職務選「現場查核」並加入
   `DEMO-B`；確認臨時密碼只在完成畫面顯示一次，離開後不再出現。
6. 在該帳號按「查看這個帳號的能力」，在「為什麼他不能做這件事？」選「管理專案
   成員」與 `DEMO-B`，按「檢查」：現場工程師沒有管理成員的角色，畫面列出可補上
   的專案角色與各自會多給的能力，由管理者自行選擇，不會自動多給權限。再改選
   「建立專案」按「檢查」：畫面指出缺的是公司層級的權限。注意「專案查閱人員」
   本來就能讀取查核任務，不能拿來製造「看不到任務」的情況。
7. 以 `demo-template-delegate` 登入「帳號」，選外部協作帳號（黃子晴），確認沒有
   「管理範本庫」；改選內部帳號（陳柏勳），勾「使用範本功能」按「開通」，畫面顯示
   「已為陳柏勳開通使用範本功能。」。自動化腳本會在驗證後撤銷這項權限，人工操作
   完成後也請撤銷，避免影響後續示範。
8. 將桌面與 360px 畫面截圖存入 `demo/screenshots/`，記下登入角色、操作步驟、
   畫面狀態和時間。只保存不含密碼或 session 的畫面。

走查步驟是操作指引；只有實際操作且留下畫面與結果記錄，才算已完成驗收。
