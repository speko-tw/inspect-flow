# 管理後台（admin-dashboard）

**代碼**：`ADM`　**Phase**：P5　**狀態**：草稿
**前置規格**：`inspection-planning`、`authentication`、`audit-log`；指標補齊另依賴 `field-evidence`、`completion-validation`
**引用意圖**：[PR-03](../../intents/02-principles.md#pr-03)、[PR-08](../../intents/02-principles.md#pr-08)、[KD-13](../../intents/03-decisions-and-stack.md#kd-13)、[KD-24](../../intents/03-decisions-and-stack.md#kd-24)、[KD-49](../../intents/03-decisions-and-stack.md#kd-49)、[04-glossary](../../intents/04-glossary.md)
**被擋議題**：無 OQ／G；全公司角色與權限畫面依尚未合併的 [#387](https://github.com/speko-tw/inspect-flow/issues/387)、[#390](https://github.com/speko-tw/inspect-flow/issues/390) 及本規格依賴處理

## 目的

讓內勤人員監看已派出的查核工作與工程師工作量，讓 Admin 管理全公司角色及查詢唯讀稽核紀錄。Dashboard 是管理工具，不是正式交付物；正式報告仍由 `report-delivery` 負責（依據：[01-overview.md](../../intents/01-overview.md#查核生命週期)，架構基準 §20.1、§20.22）。

## 範圍

**包含**：

- 管理後台唯讀總覽及 Dashboard 查詢 API：今日工作量、完成數、完成率、專案進度、工程師工作量。
- 依存取權限呈現單一專案或全部專案；全部專案總覽只供具全公司「看全部專案進度」權限者。
- 工程師工作量並列「派給誰」的待辦數與「誰查的」實際完成數。
- Admin 專用、唯讀的稽核紀錄查詢頁與 API，依專案、操作者、時間、動作類型篩選並分頁。
- 全公司角色的列表、建立、修改權限勾選、指派給使用者等管理畫面；Admin 擁有全部權限。
- 專案列表顯示成員數（#286）；若 API 契約尚未落地，先完成所需規格變更再實作。
- 已有簡便版管理功能維持由 0.2.x 規格負責；本規格承接進階管理畫面及搜尋、分頁、批次能力（依 #259 裁定與既有規格）。

**不包含**（注明移到哪份規格，或屬於哪一條非目標）：

- 建立、派出、取消、恢復或封存 Plan／Task 的操作，屬 `inspection-planning` 與現場工作流程；本規格只讀取並呈現其資料（#363）。
- 完成查核所需的證據、照片統計或影像編修，屬 `field-evidence`；依證據驗證完成的指標屬 0.6.x／0.7.x（依 #375、#388）。
- 定義角色、權限資料模型或重新制定存取控制規則；模型由 `authentication`、`domain-model` 與 intents 負責，本規格只使用（#387、#390）。
- 稽核事件寫入、保留與不可變更規則，屬 `audit-log`。
- 正式報告、報告範本及核發流程，屬 `report-delivery`。
- 全公司使用者／公司基本管理、基本角色與專案管理的 0.2.x 簡便功能；其已交付部分見 `domain-model`、`authentication` 及 #263、#265、#274、#275、#277。

## 使用情境

- 內勤人員開啟後台，依自己的專案權限查看工作量、完成情況及專案進度。
- 具全公司「看全部專案進度」權限者查看跨專案總覽，並比較各專案及工程師的進度與工作量。
- 內勤人員比較任務建議指派給誰與實際由誰完成查核，辨識代查情形。
- Admin 建立或調整全公司角色、勾選該範圍可用的權限並指派給使用者。
- Admin 依專案、操作者、時間及動作類型查詢稽核紀錄；頁面不提供修改或刪除操作。

## 需求

下列 `規格設計（非負責人裁定）` 是為讓 0.5.x 可先走通主要流程而定的呈現與計算方式；權限種類、角色範圍與特別指標依據欄列出的負責人裁定為準。

## 資料

本規格不新增領域實體。Task 的狀態、建議指派人及實際查核人由 [domain-model](../domain-model/spec.md)、[inspection-planning](../inspection-planning/spec.md) 與 [state-machines](../state-machines/spec.md) 定義；AuditLog 由 [audit-log](../audit-log/spec.md) 定義。全公司角色與權限範圍由 #387 intents 與 #390 依賴規格更新定義；本規格不先行決定資料表、權限代碼或 migration。

成員數屬 #286 尚未完成的 API 契約變更；計畫須先更新 `domain-model`，再實作後台顯示。

## 介面

畫面路由及 API 的具體路徑、查詢參數與回應 schema 由計畫依前置規格及現有 API 慣例定義；以下列出產品能力與存取邊界，不凍結尚未更新的權限代碼或欄位名稱。

| 方法 | 路徑 | 用途 | 權限 |
|---|---|---|---|
| GET | 管理後台總覽頁 | 顯示目前使用者可見的專案工作量、進度與完成指標 | 依專案／全公司權限分別檢查 |
| GET | Dashboard 彙總查詢 API | 查詢工作量、完成數、完成率、專案與工程師彙總 | 與對應頁面同範圍權限 |
| GET | 稽核紀錄查詢頁 | 篩選、分頁及檢視稽核紀錄 | Admin |
| GET | 稽核紀錄查詢 API | 依專案、操作者、時間、動作類型查詢並分頁 | Admin |
| GET／POST／PATCH | 全公司角色管理頁及 API | 列表、建立、調整同範圍權限及指派角色 | Admin；路徑與 schema 由 #390 前置規格更新定義 |

## 驗收條件

| 編號 | Given | When | Then | 對應需求 |
|---|---|---|---|---|
| ADM-AC01 | 有不同派出日期、狀態的 Task | 查詢今日工作量 | 回傳已派出未完成的工作；日期不改變計數，草稿與已完成 Task 不列入 | ADM-R02 |
| ADM-AC02 | 專案含草稿、已派出、進行中、完成及取消 Task | 查詢完成數與完成率 | 完成數依 `COMPLETED` 狀態計算；完成率依規格公布的分子、分母計算，僅計入本規格定義的狀態集合 | ADM-R03、ADM-R04 |
| ADM-AC03 | Task 有建議指派人及實際完成操作者，且部分任務由他人代查 | 查詢工程師工作量 | 並列建議指派人的未完成數與實際查核人的完成數，代查任務歸屬實際查核人 | ADM-R05 |
| ADM-AC04 | 使用者只具部分專案權限 | 查詢總覽或彙總 API | 只回傳其具權限專案的資料；不得透過參數查到其他專案 | ADM-R06 |
| ADM-AC05 | 使用者具全公司「看全部專案進度」權限 | 開啟全部專案總覽 | 可查看全部專案的進度與工作量；移除權限後不可再查 | ADM-R06 |
| ADM-AC06 | 使用者不是 Admin | 開啟稽核查詢頁或直接呼叫查詢 API | 存取遭拒且不洩漏紀錄內容 | ADM-R07 |
| ADM-AC07 | 使用者為 Admin，存在不同專案、操作者、時間與動作類型的紀錄 | 組合篩選並翻頁查詢 | 結果符合篩選、分頁穩定；查詢端點只讀，任何寫入／刪除請求不會改變紀錄 | ADM-R07、ADM-R08 |
| ADM-AC08 | Admin 建立並編輯全公司角色 | 勾選權限並指派使用者 | 只能選擇全公司範圍權限；角色指派生效；Admin 仍擁有全部權限 | ADM-R09、ADM-R10 |
| ADM-AC09 | 專案列表有不同成員數的專案 | 開啟列表 | 每個專案顯示與後端契約一致的成員數；契約未完成時不得以假值通過驗收 | ADM-R11 |
| ADM-AC10 | 0.2.x 已有使用者、公司、角色及專案簡便管理功能 | 實作進階後台 | 已完成能力不重複實作；新增搜尋、分頁或批次行為仍符合其前置規格 | ADM-R12 |
| ADM-AC11 | 0.4.x 已派出可由現場操作的 Task | 內勤開啟後台 | 可走通查看進度與工作量的主要流程；0.5.x 指標不要求依賴尚未交付的 Evidence／Completion Validation | ADM-R01、ADM-R13 |

## 待釐清

- 完成率及專案進度的分母、取消任務的排除方式，是規格設計細節；本稿先採用「已派出且非取消的 Task」作分母（含已完成、待開始、進行中）。若 #388 或前置規格的正式修訂另有明確公式，以其為準並更新本規格。此計算方式不是負責人裁定。
- Dashboard 及稽核 API 的具體 endpoint、schema、預設排序與最大 page size，待 plan 依 `api-conventions`、`audit-log` 和實際 API 確認。
- `domain-model` 尚未收錄 #286 的成員數回應欄位；先完成規格變更再實作。
- 全公司角色及權限模型已由 #387 裁定，#390 正安排相關規格更新；本規格不定義 permission code、seed、既有指派 migration 或 API 契約。
- #388 仍在 issue 內要求改寫 intents；完成驗證後「經伺服器驗證的完成」如何呈現，依更新後的 0.7.x 前置規格同步。
