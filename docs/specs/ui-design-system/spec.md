# 前端設計系統（ui-design-system）

**代碼**：`UDS`　**Phase**：P4–P7（跨階段共用）　**狀態**：草稿
**前置規格**：無；Field 與 Admin 頁面依其功能規格逐批套用
**引用意圖**：[PR-10](../../intents/02-principles.md#pr-10)、[PR-18](../../intents/02-principles.md#pr-18)、[PR-19](../../intents/02-principles.md#pr-19)、[KD-70](../../intents/03-decisions-and-stack.md#kd-70)
**被擋議題**：[#286](https://github.com/speko-tw/inspect-flow/issues/286) 的 `member_count` 契約須先依 `domain-model` 規格流程凍結；[#515](https://github.com/speko-tw/inspect-flow/issues/515) 的帳號偏好欄位與 API 須先確認規格歸屬並完成契約規格化

## 目的

讓內勤規劃者在桌機綜覽工程工作，讓現場查核員能以手機辨認任務狀態並完成下一步；在保留品牌配色與基因的同時，提供一致、清楚且不易犯錯的操作介面（依據：架構基準 §5.3、§6.1–6.2、§31；負責人指示 #534）。

## 範圍

**包含**：

- Field Web 與 Admin Web 共用的視覺主軸、語意 token、元件狀態及操作回饋。
- 清單、詳情、表單及窄螢幕逐層瀏覽的版面模式。
- 主題、無障礙、CJK 斷行與動態效果規則。
- 將 #286、#413、#514、#515、#317 的 UI 規則併入共用設計規格。

**不包含**（注明移到哪份規格，或屬於哪一條非目標）：

- 正式 API、資料表、權限及伺服器業務規則；分別由 `api-conventions`、`domain-model`、`authentication` 與功能規格負責。本規格只約束前端呈現與呼叫契約的使用方式。
- 正式報表版面與報表文件元件，屬 `report-delivery`。
- 品牌色票以外的企業品牌識別規範；本規格將已核可的操作成果回饋品牌設計系統，不取代其治理。

## 使用情境

- 內勤規劃者在桌機掃描專案、計畫、人員清單，選取一項後查看詳情或進入獨立新增／修改表單。
- 現場查核員在手機逐層進入任務，快速辨認狀態、查看步驟並執行下一個操作。
- 表單使用者能由欄旁錯誤或摘要找到問題，修正後取得載入、成功或失敗回饋。
- 帳號使用者選擇跟隨裝置、淺色或深色外觀；偏好跨裝置保存並在首次繪製前套用。

## 設計主軸與七項原則

設計主軸是「沉著、明確、操作後有可靠回饋的工程作業台」。原型保留深海軍藍、少量金色、正式繁體中文、4px 間距節奏與克制的直線感；金色只作細節提示。七項原則來自負責人核可的原型設計說明（2026-10-16）：

1. **工作入口優先呈現名稱、狀態與下一步**：列表讓使用者先辨認工作對象，再進入下一步；不以大卡片取代可掃描排列。
2. **詳情呈現工作內容，表單呈現完成條件**：詳情說明任務、地點、日期與步驟；表單依用途分組。新增與修改使用清楚分開的入口。
3. **一頁一個醒目的主操作，回饋沿用一致狀態語彙**：其他動作採較低視覺層級；操作結果可預期。
4. **表單錯誤貼近欄位並可由摘要導覽**：保留輸入內容，摘要可導向欄位，送出中防止重複提交。
5. **手機主要操作容易觸及**：主要操作與表單控制項宜至少 44×44 CSS px；窄螢幕主要操作宜全寬，次要操作降級。
6. **深色主題以語意建立層次**：使用獨立頁面、表面、文字、邊界、焦點及狀態色，不直接反轉淺色值。
7. **窄螢幕保留詞語與步驟辨識**：短標籤避免詞中斷行；長說明自然換行；步驟在窄螢幕改為直向並以文字和非顏色標記狀態。

依據：負責人指示 #534、2026-10-16 核可原型及其設計說明；通用操作要求見 PR-19。第 5 項 44×44 為設計建議，偏離時應提出可用性證據，不視為來源已裁定的不可偏離門檻。

## 語意 token

以下語意名稱與角色是本規格基準。色值以負責人核可原型（2026-10-16）為初始參考；共用元件實作時須以 WCAG 對比驗證，必要時可為滿足對比調整映射值，並記錄偏離理由。深色值未在原型中明確列出的角色，屬設計規格延伸，須在實作證據中驗收。

| 分類 | Token | 語意與初始參考 |
|---|---|---|
| 品牌 | `--color-brand-primary`、`--color-brand-accent` | 主要品牌海軍藍 `#002060`；金色 `#ffc200` 僅作細節提示，不用作一般小字或大面積底色 |
| 背景 | `--color-bg-page`、`--color-bg-surface`、`--color-bg-raised`、`--color-bg-muted` | 頁面、內容表面、浮層／凸起表面、次要區塊；淺色參考 `#f3f6fa`、`#ffffff`、`#ffffff`、`#eaf0f7` |
| 文字 | `--color-text-primary`、`--color-text-secondary`、`--color-text-inverse`、`--color-text-disabled` | 正文、次要說明、深色品牌表面上的文字、停用文字；淺色正文參考 `#101828`，小字使用已驗證對比的次要色 |
| 邊界與焦點 | `--color-border`、`--color-border-strong`、`--color-focus`、`--color-selection` | 一般／強邊界、鍵盤焦點輪廓、目前選取；焦點不得只以填色表達 |
| 狀態 | `--color-status-success`／`--color-status-success-bg`、`--color-status-warning`／`--color-status-warning-bg`、`--color-status-danger`／`--color-status-danger-bg`、`--color-status-info`／`--color-status-info-bg`、`--color-status-neutral`／`--color-status-neutral-bg` | 狀態前景與背景成對映射；狀態另有文字或圖形線索 |
| 間距 | `--space-1` 至 `--space-12` | 4px 節奏；核可原型初始階梯為 4、8、12、16、20、24、32、40、48px |
| 圓角與陰影 | `--radius-{sm,md,lg,xl}`、`--shadow-{header,panel,focus}` | 元件密度與層級；焦點陰影不得取代可見輪廓 |
| 字型 | `--font-family-sans`、`--font-size-{body,small,heading}`、`--line-height-{body,heading}` | 繁體中文優先使用 Noto Sans TC，其後退回系統字型；不得依賴外部字型才能顯示 |
| 動態 | `--motion-{fast,medium}` | 短促的 hover／狀態轉換；尊重 `prefers-reduced-motion` |

深色主題需提供以上背景、文字、邊界、焦點、選取與狀態角色的獨立映射。核可原型深色參考：頁面 `#0b1422`、表面 `#111f32`、凸起表面 `#172941`、弱化表面 `#1c3049`、正文 `#eff4fb`、次要文字 `#b8c5d6`、焦點 `#82c9f2`、選取 `#8cc4ff`。深色 primary 按鈕採 `#8cc4ff` 底與 `#0b1422` 字；色值是否沿用由對比驗收決定。

## 元件語彙與狀態

元件語彙以可組合、跨頁共用為原則。各元件實際尺寸與變體須由 token 支援，不得在頁面另造相反語意。

| 元件／模式 | 必要變體或內容 | 必要狀態／行為 |
|---|---|---|
| Button／IconButton | Button 提供 primary、secondary、tertiary、destructive；IconButton 須有可及名稱 | 互動狀態依元件狀態矩陣；每頁最多一個醒目 primary |
| Form field | label、required、hint、error；Input、Select、Textarea | 互動狀態依元件狀態矩陣；可定位錯誤貼欄位，摘要可導覽 |
| Badge／Tag | 狀態 badge 與中性 tag 分開，不以單色承載唯一資訊 | 狀態語意依元件狀態矩陣；靜態 Badge／Tag 不需互動狀態 |
| Card／Info row／Stat summary | 依掃描清單、詳情、欄位群組或彙總資料選用；列表不得一律卡片化 | 互動列依元件狀態矩陣；靜態摘要不得偽裝成按鈕 |
| Section header／Callout | Section header 可用品牌色細節分隔；Callout 說明目前情境或重要提示 | 靜態標題與提示依元件狀態矩陣；金色不作一般小字色 |
| Status feedback | inline field error、form summary、status／alert message | 依元件狀態矩陣呈現適用的非同步結果；公告使用適當語意角色並保留焦點路徑 |
| Confirm pattern | 頁內或對話框確認；顯示對象、後果、取消與具體確認動作 | 初始焦點、鍵盤操作、Escape／取消規則依操作風險定義；取消不得送出 |
| Appearance selector | 跟隨裝置（預設）、淺色、深色 | selected 需有文字或輪廓提示；偏好於首次繪製前生效 |
| Setup step | 完成、目前、未開始 | 桌機得橫向；窄螢幕改直向，文字及圖形雙重辨認 |

### 元件狀態矩陣

下表界定各元件必須支援的互動狀態與非同步回饋。未列為適用的狀態不得被視為靜態元件的驗收缺失；元件若提供額外互動，須依其實際語意補上對應狀態。

| 元件 | hover／pressed | focus-visible | selected | loading | success／error | disabled | 備註 |
|---|---|---|---|---|---|---|---|
| Button／IconButton | 可操作時必須 | 必須 | 僅選項型按鈕適用 | 觸發非同步操作時必須 | 由關聯狀態回饋呈現 | 有不可操作情境時必須 | IconButton 須保留可及名稱；loading 時防止重複送出 |
| Input／Select／Textarea | 依原生或自訂控制項互動呈現 | 必須 | 僅選項型控制項適用 | 僅非同步驗證時呈現 | invalid 由欄位錯誤呈現；驗證結果依適用行為回饋 | 有不可編輯情境時必須 | focus 與 invalid 須可辨識且不只靠顏色 |
| Form field／錯誤摘要 | 含可操作連結時依連結行為 | 含可操作連結時必須 | 不適用 | 表單非同步送出時由表單回饋呈現 | 欄位錯誤及送出結果必須 | 不適用 | 靜態 label、hint、摘要文字不需互動狀態 |
| Badge／Tag | 不適用 | 不適用 | 不適用 | 不適用 | 僅作狀態語意分類，不代表操作結果回饋 | 不適用 | 靜態呈現；若包裝成連結或控制項，由該控制項承擔狀態 |
| Section header | 不適用 | 不適用 | 不適用 | 不適用 | 不適用 | 不適用 | 若含操作控制項，僅該控制項依其元件規則呈現狀態 |
| 靜態 Card／Info row／Stat summary／Callout | 不適用 | 不適用 | 不適用 | 不適用 | 僅在承載狀態訊息時依 Status feedback 呈現 | 不適用 | 不得僅以外觀暗示可互動 |
| 互動 Card／Info row | 可操作時必須 | 必須 | 可選取時必須 | 開啟內容需非同步載入時必須 | 非同步操作結果由關聯狀態回饋呈現 | 有不可操作情境時必須 | 必須以語意控制項實作並表明可操作性 |
| Status feedback | 含重試等操作時依操作控制項 | 含可操作控制項時必須 | 不適用 | 等待中的非同步操作必須 | 成功／失敗結果依實際結果呈現 | 不適用 | 使用適當語意角色；錯誤須可理解並保留焦點路徑 |
| Confirm pattern／對話框 | 僅確認與取消等操作控制項適用 | 初始焦點及鍵盤操作依風險規則；控制項必須 | 不適用 | 確認觸發非同步操作時必須 | 操作結果由關聯狀態回饋呈現 | 操作不可用時必須 | 顯示對象與後果；取消不送出；Escape 規則依操作風險定義 |

## 版面與資料責任

- **清單＋詳情**：桌機可並列掃描清單與所選詳情；清單優先顯示名稱、狀態、摘要與下一步。手機切成清單到詳情的逐層入口，返回時保留使用者可理解的上下文。
- **新增與修改**：使用分開的入口與明確標題；不得以同一個未標示模式的表單讓人誤改既有資料（依據：PR-19）。
- **表單**：欄位依用途分組；標籤、必填、說明、錯誤與送出結果相鄰呈現。錯誤不得只用顏色表示。
- **危險操作**：確認前顯示作用對象與後果，取消不送出，明確確認後才呼叫正式寫入（依據：PR-18、PR-19）。
- **搜尋與分頁**：使用後端搜尋與 cursor；等待、沒有更多資料、空結果、載入失敗與重試均有明確回饋（#413）。
- **資料摘要**：正式畫面依凍結後 API 契約呈現 `member_count` 回傳值，不由前端推算或填入假值；只計啟用中成員為目前可推翻的設計目標，契約凍結時須確認或更新（#286）。
- **主題偏好**：帳號設定提供三態偏好，跨裝置保存；應先套用快取或等效機制再顯示主畫面，避免主題閃爍（#515）。偏好資料 API 仍依相應資料／API 規格定義。

## 待釐清

- **#286 依賴**：專案列表 `member_count` 的欄位與正式口徑尚未由 `domain-model` 凍結。2026-10-16 維護者決定以只計啟用中成員作為目標（可推翻）；須先完成 `domain-model` spec-change，確認後更新本規格，再開始依該契約實作。
- **#515 依賴**：帳號外觀偏好的欄位、儲存位置與 API 契約歸屬尚待確認。依 [#515](https://github.com/speko-tw/inspect-flow/issues/515)，開工前須確認規格歸屬；若需新增資料欄位或端點，先完成相應規格變更，合併後再實作跨裝置保存與首次繪製前套用。
- `prefers-reduced-motion` 減少動態要求屬設計系統回饋的建議，故本規格列「應」；後續若要提升為全產品「必須」，須另有明確裁定。
