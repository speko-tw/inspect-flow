## 並行分組

- 第 1 波：T1（Plan／Task 共用狀態轉換基礎）。
- 第 2 波：T2、T3（需依賴 T1，且共用 model／service／migration 檔案，初始規劃採序列執行；若實作任務能切出互不重疊檔案再調整）。
- 第 3 波：T4（依賴後端 API 契約確定）。

## 風險

- **裁定未完成即實作**：任務啟動／完成權限、Evidence 刪除及保留、Report 其他產製狀態與快照版次仍未定。以 OQ-09、G-05、G-06、G-07 及 SM-Q07、SM-Q12、SM-Q14 為開工門檻；SM-Q01／02／04／05／11／15／16 已依負責人裁定更新，不再列為門檻。
- **混淆技術提案與決策**：英文狀態名和候選轉換表不是負責人裁定。任務 issue 必須引用裁定後的 spec 版本，不可直接照草案落地。
- **任務作廢與新任務關聯遺失**：KD-55 要求完整保留舊任務和其查核資料；依 SM-Q03 規格設計保留舊任務並建立新任務後，在 domain model 中定義追溯關聯；此技術方案可由負責人推翻。
- **報告來源差異**：G-06 其他產製狀態清單衝突與 G-07 的快照時點缺漏，可能改變資料表、重試策略與產物儲存；直接核發及錯誤版本取代已裁定，其他狀態仍須先裁定並更新本規格。
- **多資料資源一致性**：Report 產製會同時處理資料庫與檔案，須依 PR-15 設計失敗回復、重試與錯誤追蹤，不得只驗成功路徑。
- **作廢 Evidence 的歷史保存**：KD-55 只決定任務作廢時證據保留並供內業查找，不裁定獨立 Evidence 的刪除 API 與保留期限；不可藉狀態實作替 G-05 拍板。
